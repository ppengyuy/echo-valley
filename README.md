# 回音谷｜刘看山陪你

> **参赛赛道**：知乎黑客松 S3 · AI・陪伴与交互赛道
>
> **交付形态**：可体验的 AI 陪伴原型（非商业化产品，不追求完美成品）
>
> **一句话定位**：面向备考学生的 AI 陪伴伙伴。依托知乎 IP 刘看山，用「山间小路」承载柔性学习计划，用「回音谷」承接情绪、感悟与自我觉察，用「静一下心」在难受的时候把人拉回平缓；不搜题、不解题、不做心理咨询。
>
> **核心创意锚点**：别的工具记的是任务、打卡和待办，用来督促人前进；回音谷记的是用户自己留下的「回音」——那些一闪而过的焦虑、触动、想不明白也想先记下来的碎片思考。AI 不用它们催人、评价人，只在用户愿意的时候，把当时属于你的声音轻轻带回给现在的你。

## 一、核心创作思路

### 1. 我们看到了什么

备考学生大量出现在知乎的提问、回答和专栏里，他们分享的不是「怎么学」的单一问题，而是一组彼此缠绕的困境：

- 不敢向熟人倾诉，怕家里失望；
- 计划一断就自责，越焦虑越学不进去；
- 读书或刷到观点时有感触，却记了也不回看；
- 休息时有负罪感，被打卡和完成率压迫；
- 对 AI「心灵鸡汤」「说教味」「假理解」高度反感。

这些痛点在公开社区里有大量第一人称原声，但现有产品要么偏向刷题提分，要么偏向心理诊断，要么用打卡和排行榜制造新的压迫感。**备考学生需要一个不带评判、不催促进度、能安静接住情绪的地方。**

### 2. 我们的答案

回音谷把「陪伴」「规划」和「缓冲」拆成三条互不污染的线：

| 空间 | 承载内容 | 气质 |
|---|---|---|
| 🛤️ 山间小路 | 学习目标、分层计划、脚印（当日任务）、复盘 | 理性、聚焦，不夹杂鸡汤 |
| 🌫️ 回音谷 | 情绪倾诉、静默留言、随笔、共读感受、回音收纳 | 安静、内敛，不要求产出成果 |
| 🧘 静一下心 | 九个自助身心调节练习（舒尔特、呼吸、54321、PMR、Stroop、微小行动、反刍打断、睡前放松、睡前思绪整理） | 低压力、随时可停，练习本身不留任何记录 |

三条线只在用户主动时打通：练习结束可以点「我想记下此刻的感受」，生成一条**可编辑的空草稿**跳到回音谷；要不要存、存什么，仍由用户自己写、自己按确认。除此之外互不干预。

复盘时，这周走过的路和这周留下的回音可以并置对照：由用户自己感受、自己言说。

**回音机制是产品的核心**：用户在对话中说出的主观感受或想法，经本人确认后才存入山谷；唤起时只带回当时的原话，不分析、不比较、不下结论。用户可以逐条聆听、归档、让回音消散或一键清空，始终掌握控制权。

### 3. 与通用 AI 的根本差异

| 维度 | 通用备考 AI / 打卡工具 | 回音谷 |
|---|---|---|
| 记忆对象 | 任务、打卡、待办 | 用户主动确认的「回音」——主观感受与想法 |
| 记忆目的 | 督促执行 | 辅助自我觉察 |
| 交互姿态 | 给答案、给方法、给激励 | 先接住情绪，再跟随用户节奏 |
| 规划方式 | 一次性生成大而空计划 | 按目标、任务、时间边界柔性分层，可随时增删调整 |
| 边界 | 容易滑向答题、诊断或鸡汤 | 明确不搜题、不诊断、不推送、不游戏化 |

### 4. 我们明确不做

不做心理诊断、测评或干预；不搜题、不解题、不代写；不私自保存回音、不自动总结或归档；不用回音催进度、做考核；不主动推送、不做积分和排行榜；不统计练习次数、时长与完成状态，不因练习行为推断情绪或改动计划；不承诺疗效、提分或「上岸」；不输出心理标签。

## 二、用户与场景价值

### 1. 服务对象

- **普通备考学生**：有明确目标，但情绪波动、计划易断、缺少稳定倾听对象。
- **高敏感、易内耗的备考学生**：更容易自我否定、害怕比较、不敢求助；对说教和鸡汤尤其敏感。

两类画像不是固定标签，而是会随备考阶段流动的状态。产品不做归类，只提供低压力的表达与整理空间。

### 2. 来自知乎的真实证据

2026-11-22，我们通过知乎开放平台 CLI 做了定向调研：17 组关键词、136 条内容（去重 125 条），人工甄别后精选 32 条作为证据底稿。素材均已脱敏，仅保留文本与裸链接。以下原声直接对应产品设计：

> 「我不是难过她让我别考，我是难过——我连让她失望的资格都没有。」
> ——知乎用户原声，对应「不敢说累、怕家里失望」

> 「我是个很容易受别人影响的人，一点点小事我都能反反复复地想到大半夜……那种无人诉说的孤独感……在最后几个月冲刺的时候，我每天都有两到三次感到崩溃。」
> ——知乎用户原声，对应「无人承接的情绪」

> 「记得越多，越焦虑。……有一些还不错的思路，当时没有记下来，它忽然就来了，又忽然就走了。」
> ——知乎用户原声，对应「零散感悟无处安放、记了不回看」

> 「一身冷汗紧紧张张补卡」「不再被打卡所绑架」「断掉的数字变成安静的指责」
> ——知乎用户原声，对应「打卡工具的压迫感」

调研也印证了话术红线：知乎上对 AI「心灵鸡汤」「说教味」「假理解」的反感是大众共识（单条回答 2804 赞）。这直接支撑我们「不做空洞宽慰、不打包票、不臆造共情」的表达原则。

> 说明：样本来自公开社区关键词检索，非随机抽样，存在幸存者偏差；结论仅作产品设计参考，不可外推为普遍结论。素材中出现躯体化、抑郁与用药表述，本调研不构成任何临床结论。

### 3. 核心场景

| 场景 | 用户状态 | 回音谷提供的价值 |
|---|---|---|
| 今天不想说话 | 有情绪但不想组织语言 | 借一句别人的话：从真实备考心境里找共鸣，不强迫表达；也可以静默留言 |
| 怕努力没有结果 | 自我否定、反复内耗 | 镜像回音：引导以好朋友口吻写给自己的话，把自我共情交还用户 |
| 计划崩了 | 自责、想放弃 | 柔性分层计划：把大目标摊成可调整的节点，超负荷就删减，不惩罚 |
| 读到戳心的观点 | 想记录但说不清 | 回音、溪边的石子、摘抄卡：把一闪而过的想法留下来，用户决定何时回看 |
| 做阶段复盘 | 想看看自己走过什么 | 双线并置：这周走过的路 / 这周留下的回音，解释权归用户 |

## 三、产品方案

### 1. 双线叙事

- **山间小路**：山巅是长期目标，沿途节点是阶段任务，脚印是当日任务；点击节点看详情。只呈现任务与节奏，不夹杂鸡汤。
- **回音谷**：一条波纹就是一条回音；刘看山安静待在山谷中。这里不要求产出学习成果。
- **静一下心**：九个练习按「专注力训练 / 节律呼吸 / 躯体放松 / 即刻疗愈·SOS / 睡眠」分类，点开是独立弹窗，随时可关，没有完成率。页面下半区是科学依据、常见问题与常驻的「安全与帮助」。
- 用户通过底部三个 Tab 主动选择链路，降低语义识别压力，也保证演示稳定；宽屏没有底部 Tab，头部留一个安静的入口。

### 2. 回音机制

- **存入**：用户说出或写下的一段主观感受，经本人确认后才存入山谷；
- **回响**：复盘时由用户主动唤起，只带回原话，不评价、不比较；
- **掌控**：可聆听、归档、让回音消散、一键清空；归档可逆，删除即时生效；
- **红线**：不定时推送、不用于催进度或考核、不回述用户没说过的话。

### 3. 「今天不想说话」

当用户没有力气倾诉时，提供一条免回应入口：借一句别人的话。内容按备考烦恼分批呈现，可换下一批，也可以从中挑一句写一句给自己。没有外部通道时使用内置 120 条本地池；接入知乎直答后，由直答生成同路人的心境表达。

### 4. 「参考一点经验」

在制定计划时，用户可以按方向、按阶段（基础 / 强化 / 冲刺）拉取一组「别人常做的备考动作」作为候选项，勾选后才进入任务框，绝不自动插入。内容来自知乎直答；未配置时回退本地通用经验池。它提供的是参考动作，不是押题、不是标准答案。

### 5. 柔性计划与导出

计划由用户目标、任务清单、时间边界和每日可投入量确定性生成，避免模型波动；用户可以随时调整节点、删减超负荷任务。提供 CSV、Excel、打印手写版三套导出，附免责备注；留白格只表示空档，不代表强制休息日。

### 6. 刘看山在场感

产品沿用刘看山简笔造型与安静、好奇、包容的原生人设，以微动作、擦雾、脚印与溪边石子等方式建立陪伴感，不做游戏化奖励，也不把 IP 变成推销吉祥物。

### 7. 存储：默认「本地珍藏」

| 项目 | 本地珍藏（出厂默认） | 会话模式（手动开启） |
|---|---|---|
| 存放位置 | 浏览器 IndexedDB | sessionStorage，页面加载即清空 |
| 刷新 / 重开浏览器 | 保留 | 消散 |
| 适用场景 | 日常自用 | 演示机、公共电脑 |

- 首次打开有一次知情确认：点「确认并继续」初始化本地库，点「本次仅用会话模式」则本次不落库、下次再问。
- 切换模式不清数据，只是换读取源；彻底清除只能由用户自己执行「全部回音消散」。
- 设置页常驻「导出 JSON 备份」「从备份恢复」「全部回音消散」（二次确认）。
- 「默认珍藏」只解决「确认过的内容跨会话不丢」，不等于「自动记录对话」——回音的显式确认动作保持不变。
- 所有数据只在本机，不上传任何后端；清浏览器缓存会丢，所以提醒定期导出。

### 8. 静一下心的边界

练习全在内存里跑，不写库、不留日志：不记录打开过哪个练习、练了多久、有没有做完；不据练习行为推断情绪或调整计划；练习结束不自动生成回音，只给一段草稿，存不存由用户点确认。工具箱是自助调节，不是心理治疗，页面与安全页都常驻危机求助入口。

## 四、技术实现方案

### 1. 总体架构

```
用户界面（React + TypeScript）
   ├── 回音谷：对话 / 波纹 / 回音列表 / 静默留言 / 确认后才存的回音
   ├── 山间小路：计划节点 / 留白格 / 三套导出
   └── 静一下心：九个练习（独立弹窗）/ 科学依据 / 安全与帮助
            ↓
本地存储层（src/persist.ts）
   ├── 默认：IndexedDB（echo / path / note 三个仓库）+ localStorage 记存储模式与首启确认
   ├── 会话模式：sessionStorage，加载即清空
   └── 导出 / 导入 JSON 备份；（IDB 不可用时静默降级到会话存储，不阻断使用）
            ↓
模型通道（按用途分流）
   ├── 陪伴对话 → 用户自填的硅基流动免费模型（Key 只在页面内存）
   ├── 经验 / 借句 → 知乎直答（由 Node 代理在服务端注入密钥）
   └── 任一通道失败 → 本地话术 / 内置池兜底
            ↓
Node 代理 server.mjs（仅托管 dist/ 与转发直答）
```

### 2. 为什么这样设计

- **轻量化可控**：不引入向量库、RAG、后台定时任务和推送服务，优先保障陪伴感稳定、可演示。
- **记忆分两层**：原话性质的「回音」、学习计划默认进本机 IndexedDB（本地珍藏），跨会话保留；需要一点痕迹都不留时切「会话模式」，刷新即散。静态标签只记录用户主动告知的偏好，不超过 100 字；回音只存原话与时间，不做摘要、不做情绪打分。
- **练习不留痕**：静一下心的九个练习只在内存里运行，不写库、不打点、不统计，避免「练了几次」变成新的考核指标。
- **用户始终掌控**：一键清空、单条归档 / 消散、导出与导入备份；用户说明情况变化时以最新口述为准。
- **确定性的计划**：计划生成与节点编辑在本地完成，保证演示稳定，不把模型波动带进计划表。

### 3. 模型与密钥安全

- **硅基流动**：用户在页面点「接入模型」自行申请并粘贴 Key。Key 只存当前页面 JS 内存，刷新即清；不写本地存储、不上传、不进代码与仓库；请求直连硅基流动官方接口，不经任何中间方。
- **知乎直答**：`server.mjs` 在 Node 侧读取平台注入的 `ZHIDA_ACCESS_SECRET`，补 `Authorization` 与时间戳后转发。密钥不进浏览器 bundle、不进源码、不进上传包。
- **用途分流**：聊天优先走硅基流动；「参考一点经验」「借一句别人的话」优先走知乎直答；任一失败自动回退本地，不打断用户。
- **静态部署模式**：若不启用 Node 代理，产品仍可完整离线体验，只是失去知乎直答通道。

### 4. 风险拦截与隐私

- 双层风险拦截：关键词黑名单 + 系统提示词约束。命中危机信号时切换**预置**兜底话术，给热线与可触达的人，不做即兴生成。
- 隐私：不收集姓名、联系方式、学校、地区等敏感信息；回音与计划只写本机 IndexedDB 或本次会话，不上传任何后端；导出文件不含真实姓名、会话 ID、设备信息或 API Key。
- 数据处置：设置页提供 JSON 导出 / 导入与「全部回音消散」（清空本机库，不可恢复）；清浏览器站点数据等同删除，首次启动与设置页都有提示。
- 局限：原型的风险识别仅用于演示层面防护，不能替代专业危机筛查；工具箱是自助调节，不提供诊断、治疗或疗效承诺。

### 5. 部署形态

项目以「前端 + Node 后端、无数据库写入」形态部署到知乎 AI Works：平台执行 `npm run build`，由 `server.mjs` 托管产物并监听平台注入的 `PORT`。审核通过后取得正式公网链接；预览链接仅作者登录可见。详细步骤见 `docs/04-知乎AI-Works部署指引.md`。

## 五、与知乎社区生态的契合度

### 1. 原生 IP，而不是借壳

刘看山是知乎原生 IP，其安静、好奇、包容的气质与「不评判、不催促」的产品定位天然一致。我们没有把 IP 当作装饰，而是让它的人设约束对话风格、视觉动效和边界表达。

### 2. 从知乎真实声音里长出来

产品的需求证据来自知乎公开内容：17 组关键词、136 条内容、32 条证据底稿。痛点、话术红线和场景价值都直接对应知乎用户的第一人称表达，不是凭空设想。

### 3. 用知乎能力，但不越界

「参考一点经验」「借一句别人的话」通过知乎直答获取素材，让社区里的经验与表达成为陪伴的一部分；同时严格限制：不批量抓取用户内容、不解析知乎原文、不输出标准答案、不冒充某个具体用户的原话。这是「借社区的声音陪你」，不是「替社区回答」。

### 4. 场景价值

- **对用户**：在备考高压期提供一个无评判、无考核、无推送的情绪安放空间，帮助看见自己的感受与变化。
- **对知乎**：把社区沉淀的真实经验转化为可体验的陪伴场景，让刘看山从内容符号变成可交互的陪伴者；作品可直接在知乎页面内运行，用户无需离开社区。
- **对赛道**：避开搜题、打卡、心理诊断三条拥挤路线，验证「情绪承接 + 自我觉察 + 柔性规划」这一中间地带。

## 六、伦理边界与局限

我们主动披露局限，而不是等评委问出来：

1. 调研素材来自公开社区关键词检索，非随机抽样，样本有限，结论不可外推；
2. 心理风险识别仅依靠关键词与提示词双层校验，难以识别隐晦、复杂的危机信号；
3. 记忆只到「本机」为止：不做跨设备同步、不做语义关联、不做遗忘之外的推断，这是主动取舍；
4. 回音唤起时机依赖模型语义理解，存在节奏生硬的可能；
5. 原型面向单人对话演示，不支持高并发多人访问；
6. 计划生成采用本地确定性模板，不等于语言模型的自由规划能力；
7. 不实现向量检索、RAG、后台推送、云端持久化，无法「长期记住一个人」；
8. 练习的科学依据只解释机制，不等于对个体的疗效；工具箱不能替代专业干预；
9. 本产品不是医疗器械、不是心理治疗，不能替代专业心理支持。

## 七、交付与体验

### 本地运行

```bash
npm install
npm run dev
```

默认地址 `http://127.0.0.1:5178`（端口被占用时用 `npm run dev -- --port 5179`）。生产构建 `npm run build`；验证线上形态用 `PORT=3000 npm run start`。

首次打开会有一次「本地珍藏」的知情确认。数据存在你自己的浏览器里：清站点数据就会没，重要的话记得到设置页导出 JSON 备份。

### 模型接入（可选，不配也能完整体验）

1. 点页面顶部「接入模型」，按引导申请硅基流动 Key 并选一个免费模型粘贴；Key 只在内存，刷新即清。
2. 本地开发可复制 `.env.example` 为 `.env` 填入 `ZHIDA_ACCESS_SECRET` 启用知乎直答代理；`.env` 已被 Git 忽略。
3. 线上部署由平台环境变量注入 `ZHIDA_ACCESS_SECRET`，绝不写入前端或源码。
