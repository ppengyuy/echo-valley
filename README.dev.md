# 回音谷 · 可体验原型（开发说明）

面向知乎黑客松 S3「AI・陪伴与交互」赛道的可体验 MVP。产品定位、人设、话术、伦理边界均以根目录 `README.md` 为准；本项目把其中的 **P0 主线** 做成了可直接运行的 Web 原型。

## 1. 运行

```bash
npm install
npm run dev
# 打开 http://127.0.0.1:5178
```

构建与本地预览：

```bash
npm run build
npm run preview
```

技术栈：Vite + React + TypeScript，无后端。CSV / Excel / 摘抄卡都在浏览器里生成，计划与回音只存在当前标签页的 `sessionStorage` 中，关闭标签页即散。

## 3. 对话引擎

默认使用**本地规则引擎**（`src/agent/engine.ts`），目的是保证黑客松现场断网也能完整演示，并且危机 / 诊断 / 搜题 / 代写等红线话术绝不会被模型即兴改写。

本地引擎会做：

- 关键词风险分级：危机 → 固定话术并停止深挖；
- 12 条固定兜底原样输出；
- 情绪意图路由（学不进去 / 计划崩了 / 累 / 比较 / 家庭 / 阅读 / 自我怀疑 / 考试压力…）；
- 回音候选判断、存入确认、拒绝后不追问；
- 复盘时先听当下，再只带回一条旧回音原话；
- 镜像回音分支；
- 天气意象按 3 轮左右出现一次，不连续重复；
- 不主动保存、不主动唤起、不催促、不贴心理标签。

### 可选：接入知乎直答（开发者 API）

1. 在项目根目录的 `.env` 里填入 Access Secret，并把开关打开：

```bash
ZHIDA_ACCESS_SECRET=你的 Access Secret
VITE_ZHIDA_ENABLED=true
VITE_ZHIDA_MODEL=zhida-fast-1p5
```

2. 改完**重启** `npm run dev`（Vite 只在启动时读取环境变量）。

3. 打开「排练」，那行小字会从“由本地对话引擎接住”变成“接着知乎直答说话”。

**为什么还要 Vite 代理**：浏览器只请求同源 `/api/zhida/v1/chat/completions`，`vite.config.ts` 在 Node 侧读取 `ZHIDA_ACCESS_SECRET`，自动补上 `Authorization: Bearer ...` 和秒级 `X-Request-Timestamp`，再转发到 `https://developer.zhihu.com`。这样 Access Secret 不会出现在浏览器 bundle 里，也绕开了浏览器跨域限制。

**模型档位**：

- `zhida-fast-1p5`：默认，更快，适合日常陪伴对话；
- `zhida-thinking-1p5`：更稳，适合需要上下文与人设的对话；
- `zhida-agent`：文档只保证 `model / messages / stream` 三个字段；角色上下文是否生效受租户授权配置影响，使用前先自测，不建议直接作为默认。

请求只发送 `model`、`messages`、`stream: false`，不额外传 temperature / max_tokens；解析 `choices[0].message.content`，忽略 `reasoning_content`。这样最贴合直答接口当前承诺的字段语义。

回答不 OOC 的三道闸：

- **提示词**：角色卡 + 4 组口吻样例 + 一组反例，明确 2–5 句、最多一个问题、不用感叹号 / 列表 / Markdown / 表情 / 括号动作。
- **口吻安检**（`src/agent/guard.ts`）：命中喊口号、说教、心理标签、系统腔、助手腔、替用户保存、英文、表情、超长、多问题等任一情况，就退回重写一次。
- **本地兜底**：重写仍不合格、接口报错、超时（20s），这一句自动换成本地引擎的回复，界面不弹错误。

> 直答的 fast 模型容易滑回问答 / 教程腔。请求时会把“只回 2–5 句、不要列表 / Markdown / 分析”的格式要求跟用户原话放在同一条 user 消息里，再交给口吻安检；两次不合格就退回本地。

配置后，**只有普通情绪对话**会走知乎直答（系统提示词见 `src/agent/systemPrompt.ts`）。危机、边界、回音确认、镜像写作、计划生成仍由本地固定逻辑承接，模型碰不到这些分支。

> ⚠️ 本地开发用 Vite 代理，适合演示。正式部署时不要把 Access Secret 放进前端；请把 `VITE_ZHIDA_ENDPOINT` 指向你自己的服务端代理，由代理注入鉴权头。构建后的 `dist` 不会自带 `/api/zhida` 代理。

## 4. 演示路径

建议按 README 第 12 章走。打开页面后：

0. 也可以直接访问 `http://127.0.0.1:5178/?demo=1`，自动放入两条演示回音与一份演示计划（仅在会话为空时生效）。
1. 点「排练」→「放入演示回音」+「生成演示计划」，得到两条虚构回音与一份可导出的计划（现场也可重新生成）。
2. 在对话里输入「最近总是学不进去，我是不是不适合考研。」→ 刘看山先接住，并出现「存入山谷」确认卡。
3. 点「存入山谷」→ 波纹漾开、Toast「山谷收下了」；点「聆听回音」查看 / 加标签 / 归档 / 让回音消散。
4. 输入「想复盘这一周」→ 先听当下；下一句再说一点感受 → 带回旧回音原话，只带回、不比较。
5. 点「梳理山间行程」→ 一次一题选完 → 看到年 / 月 / 周 / 日与留白格；可点「想再多放一件事」演示超负荷处理。
6. 「把这份计划带走」→ 分别下载 CSV（连同使用说明）、Excel，或打印手写版；失败时可用「先看文字版」兜底。
7. 首屏右下角「了解更多」展示边界；顶部可切换季节与减少动态效果。
8. 想直接看薄雾：点「排练」→「让山谷起雾」，或访问 `?demo=1&mist=1`；雾会在知乎直答回复前出现，可在雾上划开。

排练入口只在本地演示用。现场演示前建议清空会话，再放入演示回音。

## 6. 数据与边界

- 无账号、无后端、无埋点；回音与计划只存在 `sessionStorage`，关闭标签页即销毁。
- 不接通知、定时器、推送；用户主动回来才复盘。
- 导出文件不含姓名、会话 ID、设备信息或 API Key；摘抄卡也不含。
- 不实现向量检索、RAG、跨会话长期记忆、语音、PDF 批量导出、心理测评。
- 背景音乐只播放内置 CC0 / PD 音源，音频文件随项目存于 `public/audio/`，不上传、不联网拉取；不自动播放、不按情绪切歌、不推荐。
- 本地搜索是字符串匹配、置顶与标签是用户手写的会话内状态；AI 候选任务只作备选，勾选后仍需逐条确认才写入计划。
- 「今天不想说话」的铁律：不自动触发、不追问、不计次数、不产生任何记录。静默态退出不写 sessionStorage；方式 C 的换批去重靠组件内 `seenTexts` ref 累积最近 200 条（内存态，刷新即清，不落 sessionStorage），传回 `generateQuoteBatch(exclude)` 要求下一批避开。列表文案**不是逐字原声**——知乎批量输出是「问答里的说法整理」，界面标注写「备考的人 · 来自知乎问答里的说法整理」，本地池是「常见烦恼的转述」，两者都不标成某位用户的原话；「写一句给自己」只写用户自己的话并走存入确认，绝不把列表句子存成回音。
- 「溪边的石子」的铁律：别人的话只进溪滩，三条线互不串门。无来源不收、≤120 字不整段搬运；类型由用户点选、AI 不预判不打分；`touch` 类无「垫到路上」；石子原文永不直接成为回音或平石——「放进水里」只存用户自己写的文字 + `fromStone` 布尔标记，不含石子原文，导出（摘抄卡 / CSV / Excel / 文字版）永远不带他人话；删除需确认、不自动清理；不报颗数、无未读 / 推送 / 推荐。石子存 sessionStorage 的 `stones`，关闭标签页即清。
- 原型不是医疗器械，不做诊断、评估、干预；危机只做固定话术 + 专业求助引导。静默态期间出现危机表述会立即退出并原样输出第 3 条兜底话术。

## 7. 已知取舍

- 本地对话引擎是规则模拟，稳定、可离线，但语感不如真实模型；配置知乎直答后可切换。
- 知乎直答需要你自己的 Access Secret；未配置或 `VITE_ZHIDA_ENABLED` 不为 `true` 时，自动使用本地引擎。Vite 代理只在 `npm run dev` 生效，构建后的 `dist` 需要自建服务端代理。
- 计划由前端模板 + 用户写下的任务清单生成，不是真正的语言模型规划；但它与对话、页面、CSV / Excel / 打印四处使用同一份数据。
- 时间估算只做「大概放得下」的判断：用户没写每件多久时，按专注时长估一个默认值；写了下周、下下周的任务会存进同一份计划，但页面上只展开「这一周」，其余在向导最后一眼和 CSV 里能看到。
- 节点微调全部在前端本地状态完成，不调用模型；只有用户主动点「重新标一遍」才会回到向导。
- 「口袋」里的东西不计容量、不进导出；「已放下」仍留在周视图里摊平（平石压扁转灰），不划掉、不标红，也不占当周容量，也不自动重排其他事。
- 拖拽用浏览器原生 drag & drop，触屏设备退化用编辑面板里的日期选择。
- 「存入山谷」的涟漪只在回音谷面板内部展开：大光圈 + 柔光底 + 一句原话，持续约 3 秒；不会盖住左边小路、页头或页面背景。
- 刘看山只用现有极简剪影 + 自绘线条做微动作，不直接使用官方像素插画或二创素材；正式对外物料需按知乎刘看山 IP 规范另行确认授权。
- 眨眼 / 点头 / 尾巴 / 闲置小书 / 擦雾都是前端 CSS / SVG；「减少动态效果」下全部静态化。`?idle=1`、`?mist=1` 仅为演示与自测参数，不影响默认行为。
- 新旧回音关联提示已落地（P1-03），但**判定全在本地**：`src/agent/relate.ts` 用去虚字后的字符二元组算相近度（阈值 0.25、共有二元组 ≥3、同标签加权 0.15），只挑分最高的一条，宁缺毋滥。不调用模型，因为模型会把没关系的两段说成"有内在关联"，那等于替用户下结论。触发还要同时满足：未归档回音 ≥5 条、旧回音非镜像且存入超过 10 分钟、本会话没点过「先不用」、最近 5 分钟没触发危机或边界兜底、不在静默态、这一对没提示过。提示只出现在回音谷面板里，不在对话区发消息；「听一听」只带回原话与时间标签，不做分析不做对比。
- 关联提示的 `relateHint` 不跨刷新（提示是当下那一刻的邀请），但 `relateMuted` 与 `relatedPairs` 随会话保留；回音被归档、消散或清空时提示同步收起。
- 归档 / 标签 / 计划均在当前会话内生效，刷新保留，关闭标签页即清空。
- **空心规划节点拖拽调时间不做**：年 / 月 / 周 / 日是层级而非日期，直接拖拽会语义混乱。改日期的主路径是拖拽周计划卡片到别的日子，触屏 / 键盘用浮层里的日期选择兜底（见 README 7.11.9 第 3 条）。
- 时间线任务区已按「任务安排 / 进度记录 / 自留独白」三块重排，仅视觉分组变化，字段与五态枚举不变；底部页脚统一为「周期时间 + 本周总时长预算」。
- 计划生成加载已从光圈呼吸换成小动物逐帧走路（200ms 一帧 / 4 帧循环），聊天「正在输入」用小动物眨眼，二者在「减少动态效果」下都退化为静态。
- 节点详情里的独白**只有主动点「把这句话存为回音」才存入**，不自动保存，符合 README 10.3 的回音伦理约束。
- 计划向导标签仍是「选中即进入下一步」，返回上一步可回填修改；与 README 7.11.3「填充后可停在同一页二次修改」的路径不完全一致（见 7.11.9 第 7 条）。
- 终版设计交付规范与完整动效总附表见 README 7.11；状态以 README 8.4 五态为唯一枚举，口语里的「在路上 / 走完啦」不算新状态。
- 内置音乐 8 首均为 Wikimedia Commons 的 CC0 / Public Domain 素材：山谷舒缓 5 首（雨落屋檐、林间有风、浅溪碎石、夜色原野、远岸潮声），山间向前 3 首（慢慢向前、清晨琴声、木吉他暖）。每首的原始文件名、许可类型见 `src/data/music.ts` 顶部注释；音频不承载任何用户数据。
- 原「细白的安静」白噪音仅 1.65 秒、听起来像没声音，已移除，换成 30 秒「雨落屋檐」；`relaxing-piano.wav` 约 12MB，若要瘦身可换等价 CC0 源或转码，不影响功能。
- AI 候选任务优先走知乎直答（`generateCandidateText`），未配置 / 失败 / 超时自动降级本地通用池，并告知用户；模型输出会过滤"以下是常见动作："一类标题行，避免把标题当成一件事。候选不绑定时长、不押题、不改已有计划。
- 候选池已按「方向 × 阶段」重构（P1-07）：`LOCAL_POOL` 为 `Record<方向, Record<'base'|'build'|'sprint', string[]>>`，考研 / 考公 / 考证 / 期末 / 通用各阶段 ≥12 条，够连换两三批不重复。`generateCandidates(goal, opts?)` 的 `stage` 与 `exclude` 都可选，所以 `ItemEditor` 与 `PlanWizard` 的旧调用不改也能跑。阶段只决定这一批给什么：默认永远是「全部」，不按 `horizon`、考试时间或计划进度自动选；阶段不写进 `PlanItem`、不进任何导出，CSV 仍是 `CSV_HEADERS` 的 12 字段。换一批时已勾选的条目固定在弹窗顶部「已经挑了的」分组，确认数量照常累计；某个阶段的条目全给过后显示"差不多都在这里了"，再点从头循环。三个入口里只有弹窗有阶段选择，编辑卡与向导只加「换一批」，避免三处都变复杂。
- 本地音频（P1-05）只在内存里：`localTracks` 不进 sessionStorage，`objectURL` 在移除、组件卸载、`pagehide` 三处 revoke；`echo-valley-local-audio-meta` 只存 `{name, size}` 用于刷新后的灰色记录，`LAST_TRACK_KEY` 不写 `local-` 前缀的 id，避免刷新后指向失效 URL。选完文件只选中不播放（选文件 ≠ 现在想听），上限 5 首，>50MB 先问一句再放进来，MIME 与扩展名都不像音频的直接拒掉，`<audio>` 解码失败的会提示并移走。不读 ID3 标签与封面，不按情绪推荐或自动切到本地曲目，全程 0 个网络请求。
- 回音置顶上限 3 条写在 reducer（`TOGGLE_PIN`），达到上限时 UI 置灰其余按钮并给温和提示；置顶只是排序标记，不做"重要 / 紧急"等压力标签。
- 回音正文在线编辑（P1-08）只走 `UPDATE_ECHO` 的 `text` 字段：默认只读，必须点「改一改这句话」才进编辑态，改完点「留下改好的这句」才写入，`createdAt`、`mirror`、`tag`、`link` 等一概不动——改的是说法，不是"这句话什么时候被听见"。空白内容禁用保存，内容没变则直接退出并提示。编辑态下复制、摘抄卡、归档、消散与下方标签 / 链接区全部禁用，避免两处保存互相打架；改了没保存就按 ESC 或点背景时，用捕获阶段的监听挡在 Modal 自己的 ESC 处理之前，先问一句再决定丢不丢。正文只存用户自己敲出来的字，不润色、不改写、不调用模型。`echoOpen` 由 id 实时查找，所以保存后弹窗、列表、搜索、摘抄卡会一起更新。
