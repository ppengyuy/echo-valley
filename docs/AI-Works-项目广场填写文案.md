### 回音谷：把说不出口的情绪留在山谷里

回音谷是面向备考学生的 AI 陪伴原型。依托知乎 IP 刘看山，用「山间小路」承载柔性学习计划，用「回音谷」承接情绪、感悟与自我觉察。不搜题、不解题、不做心理咨询。

【在此处点击工具栏「图片」上传 cover.png】

### 一、为什么做

备考学生大量出现在知乎的提问、回答和专栏里，他们分享的不是「怎么学」的单一问题，而是一组彼此缠绕的困境：

- 不敢向熟人倾诉，怕家里失望；
- 计划一断就自责，越焦虑越学不进去；
- 读书或刷到观点时有感触，却记了也不回看；
- 休息时有负罪感，被打卡和完成率压迫；
- 对 AI「心灵鸡汤」「说教味」「假理解」高度反感。

需求证据来自我们 2026-11-22 做的定向调研：17 组关键词、136 条内容（去重 125 条），人工甄别后精选 32 条作为证据底稿，素材均已脱敏。现有产品要么偏向刷题提分，要么偏向心理诊断，要么用打卡和排行榜制造新的压迫感。备考学生需要一个不带评判、不催促进度、能安静接住情绪的地方。

### 二、产品怎么做

- **双线叙事**：「山间小路」只放目标、节点与当日任务；「回音谷」只承接情绪与感悟。两条线只在用户主动复盘时并置，解释权归用户。
- **回音机制**：用户说出或写下的一段主观感受，经本人确认后才存入山谷；唤起时只带回原话，不分析、不比较、不下结论。可逐条聆听、归档、让回音消散或一键清空。
- **今天不想说话**：提供免回应入口「借一句别人的话」，按备考烦恼分批呈现、可换下一批，也能挑一句写给自己。
- **参考一点经验**：制定计划时按方向、按阶段拉取一组「别人常做的备考动作」作为候选项，勾选后才进入任务框，绝不自动插入。
- **柔性计划与导出**：由目标、任务、时间边界和每日可投入量确定性生成，可随时删减超负荷任务；提供 CSV、Excel、打印手写版三套导出。
- **刘看山在场感**：沿用简笔造型与安静、好奇、包容的人设，用微动作、擦雾、脚印与溪边石子建立陪伴感，不做游戏化奖励。

### 三、与知乎社区生态的契合

- **原生 IP**：刘看山的安静、好奇、包容与「不评判、不催促」的产品定位天然一致，人设约束了对话风格、视觉动效和边界表达，而不是把 IP 当装饰。
- **从知乎真实声音里长出来**：痛点、话术红线和核心场景都对应知乎用户的第一人称表达，不是凭空设想。
- **用知乎能力但不越界**：「参考一点经验」「借一句别人的话」优先走知乎直答，让社区里的经验与表达成为陪伴的一部分；同时不批量抓取用户内容、不解析知乎原文、不输出标准答案、不冒充具体用户的原话。
- **场景价值**：对用户，是高压备考期一个无评判、无考核、无推送的情绪安放空间；对知乎，把社区沉淀的真实经验转化为可体验的陪伴场景，让刘看山从内容符号变成可交互的陪伴者；对赛道，验证「情绪承接 + 自我觉察 + 柔性规划」这一中间地带。

### 四、技术实现

- **前端**：React + TypeScript + Vite；数据只存浏览器 sessionStorage，无数据库、无云端持久化，关闭标签页即散。
- **模型按用途分流**：陪伴对话走用户自填的硅基流动免费模型；「参考一点经验」「借一句别人的话」优先走知乎直答，由 Node 代理在服务端注入密钥；任一通道失败自动回退本地，不打断体验。
- **密钥安全**：硅基流动 Key 只存页面 JS 内存，刷新即清，不写本地存储、不上传、不进代码与仓库；知乎密钥由平台环境变量注入 Node 侧，不进浏览器 bundle、不进源码、不进上传包。
- **风险与隐私**：关键词黑名单 + 系统提示词双层拦截，命中危机信号时切换预置兜底话术；不收集姓名、联系方式、学校、地区等敏感信息；导出文件不含真实姓名、会话 ID、设备信息或 API Key。
- **部署**：以「前端 + Node 后端、无数据库写入」形态发布到 AI Works，`npm run build` 构建，`server.mjs` 托管产物并监听平台注入的 `PORT`。

### 五、如何体验

- 完整源码与工程规范：https://github.com/ppengyuy/echo-valley
- 本地运行：`npm install && npm run dev`，默认 http://127.0.0.1:5178
- 模型接入为可选项：不配 Key 也能完整体验本地话术与内置内容池；点页面顶部「接入模型」可自行申请并粘贴硅基流动 Key。

### 六、边界与局限

- 调研为公开社区关键词检索，非随机抽样，结论不可外推。
- 风险识别仅用于演示层面防护，不能替代专业危机筛查。
- 记忆仅会话内生效，不做跨会话长期记忆与语义关联，这是主动取舍。
- 原型面向单人演示，不支持高并发；不是医疗器械或心理治疗，不能替代专业心理支持。

### 给平台 Agent 的提示词（源码发布时直接复制）

```text
这是一个「前端 + Node 后端、无数据库写入」的全栈 npm 项目，请按全栈分支探测，不要识别成纯静态。
根目录就是组件目录：package.json + package-lock.json + server.mjs + src/ + public/ + vite.config.ts。
构建命令：npm run build
启动命令：npm run start
端口：读取环境变量 PORT，默认 3000，监听 0.0.0.0。

它在 Node 侧读取环境变量 ZHIDA_ACCESS_SECRET 补鉴权头，该密钥只在服务端运行时使用。

请把 ZHIDA_ACCESS_SECRET 作为平台环境变量注入，不要写进源码、不要写进 VITE_* 变量、不要放进上传包。
如果探测结果只有 frontend.deploy.json、没有 backend.deploy.json，说明没识别到 Node 服务，知乎直答会失效，请重新探测全栈分支。
项目不接账号登录、不含数据库；数据只存在浏览器 sessionStorage。
```

### 为什么不用 CloudBase Skill 包

知乎官方的 `zhihu-ai-works-deploy-helper` 已安装并做过只读探测，结果 `blocked`：它不支持自定义运行时环境变量，保留知乎直答就必须把密钥明文固化进交付 ZIP，与密钥安全铁律冲突；同时残留的 `frontend/` 演示脚本触发云函数只读文件系统阻断。因此不走 CloudBase 分支，改用 AI Works「源码发布」——平台支持在环境变量里注入 `ZHIDA_ACCESS_SECRET`，知乎直答可以正常保留。
