# 04 · 部署到知乎 AI Works（面向开发者）

> 适用场景：本地已能运行、**不依赖独立数据库**的前端 / 轻量全栈项目，发布到知乎 AI Works 并取得一个可分享的访问链接。
>
> 本项目（回音谷）符合这个前提：Vite + React 前端，加一个**极小的 Node 代理**（`server.mjs`），数据存在浏览器会话里（sessionStorage），不接任何外部数据库。原本未使用的 Python `backend/` 目录已移除。
>
> 两种发布方式：① 纯静态（不含 Node 代理）——保留全部本地功能与用户自填模型；② 前端 + Node 后端（推荐）——额外保留知乎直答，让「参考一点经验」「借一句别人的话」继续走知乎生态。

---

## ⚠️ 先读这一段：密钥安全铁律

**贯穿下面所有步骤，任何一步都不得违反：**

1. **只引导用户自己在本地填写 API Key**。你（无论是 Agent 还是部署者）**不得索要、不得记录、不得展示**用户的密钥。
2. **不得把密钥写进源码、仓库或上传包**。不要 `console.log` 密钥，不要拼进 URL，不要写进 `.env` 一并上传，更不要提交到 Git。
3. **CLI / 平台若提示「注入环境变量密钥」，只指导用户在自己本地配置**，不要替用户填、不要回显、不要把值贴到对话里。
4. **打包 / 上传前必须复核**：敏感信息没有进入上传包。本项目已把 `.env`、`.env.*`、`.workbuddy/` 等写入 `.gitignore`，打包时也要按同样规则排除。
5. 本项目在界面里提供的「接入模型」入口，密钥**只存当前页面内存**，刷新即清；不写浏览器存储、不上传、不进代码与包。Agent 不得读取或导出这个 Key。

一句话：**Key 属于用户，只经过用户自己的浏览器，直连模型服务商，不经任何中间方。**

## 一、发布步骤

### 1）登录项目广场，创建作品

打开 <https://www.zhihu.com/project-square>，登录知乎账号，点击「创建项目」，填写项目名称、一句话简介、项目类型、版本与说明。中途可以存草稿。

### 2）选择「源码发布」，让本地 Agent 确认构建

在项目内容一步选择**源码发布**。复制平台给出的提示词，发给你的本地 Agent，让它在项目根目录执行页面给出的命令，**先在本地确认能构建成功**（本项目对应 `npm run build`）。

> 本地构建通过再上传，能省掉绝大多数「云端构建失败」的往返。

### 3）上传生成的 ZIP

把本地确认过的工程打成 ZIP 上传。若找不到生成的文件，让 Agent 帮你拷贝到桌面再上传。

打包时注意（对应上面的安全铁律）：

- 包含：`index.html`、`package.json`、`package-lock.json`、`vite.config.ts`、`tsconfig.json`、`server.mjs`、`src/`、`public/`、必要的文档与示例配置 `.env.example`，以及 `.env.production`（只含公开开关 `VITE_ZHIDA_ENABLED`，用于启用直答通道，**不含任何密钥**）。
- **排除**：`.env`（真实密钥）、`node_modules/`、`dist/`、`.git/`、`.workbuddy/`、`.box-agent*/`、`*.genie`、`demo-site/`、`frontend/`（早期残留副本）、`design/`（封面设计稿）、`cover*.png`（封面单独在表单上传）。

### 4）观察构建状态，失败就交回 Agent 修

平台会依次经历上传、构建中、构建完成 / 失败。**构建失败时，把平台给出的完整报错（错误码 + 日志摘要）原样交给本地 Agent 修复**，改完重新上传即可。不要自己猜原因改配置。

常见坑（本项目已处理）：

- 两种模式都先跑 `npm run build`。**纯静态模式**平台托管 `dist/`，不用自己监听端口；**全栈模式**由 `server.mjs` 托管 `dist/` 并代理 `/api/zhida`，监听 `0.0.0.0:${PORT:-3000}`，启动命令 `npm run start`。`vite.config.ts` 里的 `127.0.0.1:5178` 只用于本地开发。
- 依赖声明要完整：本项目用 npm，`package.json` + `package-lock.json` 都在；`server.mjs` 只用 Node 内置模块，不新增依赖。

### 5）没有独立数据库：用文件 / 浏览器存储代替

**平台暂不提供独立托管的数据库服务。** 需要持久化的地方请改为：

- 本项目现状：会话数据用浏览器 `sessionStorage`（键 `echo-valley-session-v1`），关闭页面即散，符合平台能力，无需改造。
- 若确需落盘的结构化数据：用 JSON 数据文件随工程一起打包读取，或改用平台提供的托管能力。**不要依赖运行时写入容器本地的 SQLite 文件**——容器重启后文件会丢失。

### 6）预览链接 ≠ 正式链接

- 带 `preview` 的预览链接**只有作者登录后可见**，别人打不开，这是正常的。
- 预览通过 → 提交审核 → **审核通过并确认发布后**，平台才会生成正式的公网访问链接。
- 审核期间别人看到的是占位状态，不是你的作品出了问题。

## 二、保留知乎直答：全栈部署分支（推荐）

平台明确支持**「前端 + Node 后端、不含数据库写入」**的项目。本项目为此准备了 `server.mjs`，它只做两件事：托管构建好的 `dist/`，以及把 `/api/zhida/v1/chat/completions` 转发到知乎开发者接口。不写数据库、不存用户数据。

### 工作方式

- 浏览器仍请求同源 `/api/zhida/v1/chat/completions`，前端代码**不用改**。
- `server.mjs` 在 Node 侧读取 `ZHIDA_ACCESS_SECRET`，补上 `Authorization: Bearer ...` 与 `X-Request-Timestamp` 后转发；密钥**不进浏览器 bundle**。
- 已按用途分流：陪伴对话优先用用户自己填的硅基流动 Key；「参考一点经验」「借一句别人的话」优先走知乎直答，只有直答失败/未配置时才退回本地池，不会被硅基流动顶替。
- 仓库里的 `.env.production` 只含公开开关 `VITE_ZHIDA_ENABLED=true` 与模型名，**不含密钥**；它让生产构建启用直答通道。纯静态部署若保留它而服务端没有代理，会自动回退本地，不影响使用。

### 本地验证

```bash
npm run build
ZHIDA_ACCESS_SECRET=你的密钥 PORT=3000 npm run start
# 另一个终端：
curl http://127.0.0.1:3000/                     # 应返回 index.html
curl -X POST http://127.0.0.1:3000/api/zhida/v1/chat/completions \
  -H 'Content-Type: application/json' -d '{}'   # 有 Key 才转发，无 Key 返回 503
```

### 上传到 AI Works 时必须让平台识别为全栈

1. 选择「源码发布」后，把平台提示词发给 Agent，并明确说：**这是前端 + Node 后端的全栈项目，无数据库写入；构建 `npm run build`，启动 `npm run start`，端口读环境变量 `PORT` 并监听 `0.0.0.0`。**
2. ZIP 必须包含 `server.mjs` 与根 `package.json`；平台探测后应生成 `backend.deploy.json`（或前后端双描述符）。若平台只给出 `frontend.deploy.json`，说明它没识别到 Node 服务，此时知乎直答不会运行——把这段说明原样反馈给平台 Agent 重新探测。
3. 密钥注入：在平台提供的**环境变量**里填 `ZHIDA_ACCESS_SECRET`，运行时由 Node 读取。**不要**把它写进 `VITE_*`、源码、`.env` 或随 ZIP 上传。若平台提示「把密钥写入文件后构建」，只在本地用它跑通验证，打包前务必排除该文件；正式运行仍以平台环境变量为准。
4. 审核声明如实填写：本项目不接账号登录、不含数据库；「是否含大模型内容」按实际选是（接了知乎直答 / 可选硅基流动）。

> 平台后端分支的公开案例较少，首次上传可能需要在「前端 + Node 后端」识别上多试一次。即便全栈识别失败，退回纯静态模式仍能完整使用所有本地功能与用户自填模型，只是失去知乎直答。

## 三、调用模型：硅基流动免费模型

作品默认用内置的话术陪聊，不花钱、不联网也能完整体验。如果想让模型临场组织语言，用硅基流动的免费开源模型：

1. **注册一次**：打开 <https://cloud.siliconflow.cn/>，用手机号注册登录（免费模型通常需要实名认证）。
2. **申请一个 Key**：到 <https://cloud.siliconflow.cn/me/account/ak> 创建 API Key，复制备用。
3. **选免费模型**：在 <https://siliconflow.cn/pricing> 看哪些模型标价为 0。免费是**活动规则、会变动**，以价格页实时显示为准，不要把某个模型当成永久免费。
4. **在作品里接入**：点页面顶部的「接入模型」→ 三步引导 → 粘贴 Key → 选模型 → 点「就用它」。

> 本项目预置了几个曾标价 0 的对话模型作为快捷项（GLM-4-9B、GLM-Z1-9B、星辰 29B、混元 7B），也允许手填任意模型 ID。

### 密钥机制（必须如实向用户说明）

| 项 | 机制 |
|---|---|
| 存在哪 | 仅当前页面 JS 内存 |
| 刷新 / 关页 | 立即消失 |
| 本地存储 | 不写 localStorage / sessionStorage / IndexedDB / Cookie |
| 网络 | 只发往硅基流动官方接口 `api.siliconflow.cn`，作为鉴权头，不经中间方 |
| 源码 / 仓库 / 上传包 | 不含密钥 |
| 他人 | 看不到、拿不到；每人填自己的 Key |

**Agent 与开发者不得读取、记录、展示用户填入的 Key。**

## 五、部署后的功能边界（重要）

| 功能 | 是否保留 | 说明 |
|---|---|---|
| 刘看山形象、溪边石子、真题、候选任务、打印、环境音 | ✅ 完整保留 | 全是前端静态资源与逻辑，`npm run build` 后照常运行 |
| 陪伴对话 | ✅ 保留 | 默认走本地话术引擎；用户点「接入模型」填自己的硅基流动 Key 后走在线模型 |
| 制定计划时的「参考一点经验」 | ✅ 全栈模式可保留知乎来源 | 纯静态：本地通用经验池，或用户填硅基流动 Key 后由模型在线生成；全栈模式：继续走知乎直答代理。**注意它本来是模型生成「别人常做的动作」，不是知乎搜索接口** |
| 「今天不想说话 → 借一句别人的话」列表、分批、换批、写一句给自己 | ✅ 保留 | 纯静态：本地 120 条池或硅基流动；全栈模式：可继续走知乎直答，列表 / 分批 / 换批 / 写一句给自己都不变 |
| 知乎直答（知乎生态通道） | ✅ 全栈模式保留；❌ 纯静态不保留 | `server.mjs` 在 Node 侧注入 `ZHIDA_ACCESS_SECRET` 并转发 `/api/zhida`。纯静态没有这个代理，会回退本地。**不要把 Secret 写进 `VITE_*` 或源码**，那会泄露给所有访客 |
| 注册登录、数据库、后端 REST 接口 | ❌ 已移除 | 未使用的 `backend/` 目录已从仓库删除；前端没有调用它，不影响任何可见功能 |
| 用户填写的模型 Key | ✅ 保留且更安全 | 仍只存页面内存、刷新即清；每人填自己的，不进仓库和上传包 |

预览链接带 `preview` 且仅作者登录可见属正常；审核通过、确认发布后才有正式公网链接。
